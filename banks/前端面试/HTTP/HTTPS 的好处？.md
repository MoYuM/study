HTTPS = HTTP + TLS，真正的好处集中在 TLS 带来的三个安全保障，外加一个附带的业务收益：

- **加密**：传输内容即使被截获也读不懂，防止明文被窃听。
- **身份验证**：CA 签发的证书确认服务器身份，防止中间人伪造服务器发起攻击（MITM）。
- **数据完整性**：传输途中数据被篡改能被发现（校验失败会中断连接）——是"改了就露馅"，不是"读不懂"，和加密是两件不同的事。
- **SEO 更友好**：搜索引擎（尤其谷歌，2014 年起明确将 HTTPS 列为排名信号）同等条件下给 HTTPS 站点更高权重；浏览器也会给 HTTPS 站点显示锁形图标，提升用户信任感。

## 不算"好处"，是用 HTTPS 要付出的代价 / 客观事实（容易被误列进好处）

- **需要证书**：必须由权威 CA 签发证书，涉及申请、续期、管理成本，是前提不是收益。
- **端口 443**：只是识别性事实（区别于 HTTP 默认的 80 端口），数字本身不带来任何安全属性——真正有用的是"用了和 HTTP 不同的端口"这件事本身，能让 HTTP/HTTPS 在同一服务器共存、也方便网络层强制流量走加密通道；但换成哪个端口号都一样，"443"这个数字没有特殊意义。
- **速度比 HTTP 慢**：握手 + 加解密带来额外开销，字面意思就是"更慢"——这是代价，不是好处（现代硬件和 TLS 1.3 已大幅缩小这个差距）。
