响应式布局：同一套页面在不同尺寸设备上都能合理展示，核心手段是相对单位（等比缩放）+ 媒体查询（切换布局结构）。

## 发展史（问题 → 方案的链条）

**❓ 固定像素布局在不同尺寸屏幕上要么留白要么挤爆**
早期网页按桌面屏幕设计固定像素宽度。2007 年 iPhone 发布、智能手机普及后，同一个固定宽度的页面在手机上要么被压得字都看不清，要么得横向滚动才能看全，问题被急剧放大。

**✅ 用百分比等相对单位做「流式布局」**
把宽度从固定像素改成百分比，让页面能按容器比例伸缩，这在响应式概念出现之前就已经是常见技巧（"流式布局" fluid layout）。

**❓ 流式布局只能连续缩放，没法在小屏幕上"改结构"**
百分比只能让三栏一起等比例缩小，缩到手机屏幕上就是三条挤在一起看不清的细栏——它解决不了"小屏幕该换成一栏"这种结构性调整。

**✅ CSS3 Media Queries：按视口特征切换整套样式规则**
Media Queries 让开发者可以按视口宽度等特征应用不同的 CSS 规则，在指定的断点处直接切换布局结构（比如三栏变一栏）。该模块 2012 年成为 W3C 正式推荐标准，但主流浏览器的实现早于这个时间点。

**❓ 但移动浏览器默认按"虚拟桌面宽度"渲染页面，媒体查询检测不到设备真实宽度**
早期移动浏览器为了兼容桌面页面，默认把视口伪装成约 980px 宽的"虚拟桌面"，再整体缩小显示、允许用户手动缩放——这导致基于视口宽度的媒体查询判断不到手机屏幕的真实宽度。

**✅ 2007 年，iPhone/Safari 引入 viewport meta 标签**
`<meta name="viewport" content="width=device-width, initial-scale=1">` 让页面按设备真实宽度渲染，不再套用虚拟桌面宽度，之后被其他移动浏览器普遍采纳，媒体查询才算真正在移动端跑起来。

**❓ 流式网格、弹性图片、媒体查询三件套零散使用，缺一套统一方法论**
三种技巧各自能用，但当时是分散的、零散的实践，没有一个系统的名字和方法论把它们串起来教给开发者。

**✅ 2010 年，Ethan Marcotte 发表《Responsive Web Design》，正式提出这个方法论**
Marcotte 在 A List Apart 上的这篇文章把「流式网格 + 弹性图片（`max-width:100%`）+ 媒体查询」整合成一套系统方法，「响应式网页设计（Responsive Web Design）」这个名字由此确立并被行业采纳。

**❓ 百分比是相对父元素算的，嵌套一多算起来很麻烦，字体用 px 也没法整体缩放**
百分比布局在多层嵌套时，换算关系会变得复杂；而字体大小如果固定用 px，没法随屏幕整体等比缩放。

**✅ CSS3 陆续补充 rem（相对根字号）、vw/vh（相对视口）等新单位**
两者被主流浏览器广泛支持的时间点并不相同：`rem` 相对根元素字号计算，支持较早（Chrome/Firefox/Safari 2009-2010 年前后就已支持，主要是 IE 拖到 2013 年 IE11 才跟上）；`vw`/`vh` 直接相对视口宽高计算，反而支持更晚（Chrome/Firefox 到 2013 年前后才广泛支持）。移动端常见做法是用 JS 动态设置根字号，或直接用 `vw`，配合 `postcss-px-to-viewport` 等工具自动换算设计稿尺寸。

**现状：相对单位负责等比缩放，媒体查询负责切换结构，flex/grid 负责弹性布局本身**
三者组合是当今响应式布局的标准工具箱，「移动优先」（Luke Wroblewski，2011 年提出的设计理念，主张先为小屏幕设计再逐步增强）成为主流设计出发点；此外 viewport meta、图片 `srcset`/`picture` 也是配套的响应式图片方案。
