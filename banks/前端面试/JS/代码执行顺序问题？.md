考点是事件循环：同步代码 → 当前任务(task)结束后清空所有微任务(microtask) → 取下一个任务。

分析口诀：先走同步；遇到 `Promise.then`/`await` 之后的代码进微任务队列；`setTimeout`/`setInterval` 进任务队列（社区俗称"宏任务"，规范里没这个词）；每个任务执行完都会把微任务清空。`async` 函数中 `await` 右侧表达式同步执行，其后的代码相当于 `.then` 回调。

## 发展史（问题 → 方案的链条）

**❓ HTML 事件循环模型里一直只有一种排队方式——task：一段 script、一次事件回调、一次 setTimeout 回调……整个跑完才轮到下一个。ES6（2015）引入 Promise 后，`.then()` 里的回调该排去哪？**
如果也扔进这条 task 队列，就得跟计时器、DOM 事件抢位置，等待时间不可控，达不到 Promise 想要的"尽快异步执行"效果。

**✅ ECMAScript 规范另起一套排队机制，叫 Job**
`PromiseReactionJob`、`PromiseResolveThenableJob` 都是 Job，执行时机写死为"当前没有正在运行的执行上下文、调用栈清空时立即执行"，比排队等下一轮 task 优先得多。

**❓ 规范讲的是 Job，但 Promise 要跑在浏览器/Node 这些宿主环境已有的事件循环里，Job 和宿主的 task 队列怎么对接？这层关系当年只在邮件列表里讨论过，没有写死（Jake Archibald 2015 年的文章里原话是 "the relationship isn't explicit aside from vague mailing list discussions"）。**
对接方式不标准化，各引擎实现就可能不一致。

**✅ HTML Living Standard 把这层对接关系标准化，加一个 microtask queue**
规定"每个 task 执行完、调用栈清空后，必须立刻把 microtask queue 清空（执行过程中新入队的也要清完）才能进入渲染或取下一个 task"。ES 规范里的 Job 落地为 HTML 规范里的 microtask，`queueMicrotask()` 后来顺势成为标准 API。

**❓ 至此规范里出现的词只有 task 和 microtask（HTML Standard 8.1.7 节、MDN 的 Microtask guide 都是如此），"宏任务（macrotask）"这个说法是哪来的？**
"microtask"一词诞生后，开发者写文章对比两者时，自然想找个对仗的名字指代"microtask 之外的那个 task"。

**✅ macrotask 只是社区（教程、博客、翻译文章）自发生造的俗称，不是规范用词**
它就是 task 的另一个名字，不代表规范里另有一种更"宏观"的任务类型——连最早系统梳理这套机制的 Jake Archibald 那篇经典文章全篇都只用 task/microtask，没有出现过 macrotask。

**现状：task/microtask 是排队方式，同步/异步是另一个维度，两者不要混着背**
规范原词是 task（任务）vs microtask（微任务）；"宏任务"只是 task 的俗称。事件循环模型本身根本没有"同步/异步"这个概念——一段 script、一次事件回调、一次 setTimeout 回调，作为整体就是一个 task，这个 task 内部代码从头跑到尾都是顺序执行的，只是执行过程中把 `.then` 回调丢进 microtask 队列、把 `setTimeout` 回调丢进下一个 task 而已。"同步/异步"是写代码时描述"是否阻塞后续代码"的心智模型，属于代码语义层面，和 task/microtask 这种事件循环排队机制不是一回事。

## 相关考点

- **`queueMicrotask()`**：标准 API，手动把回调塞进 microtask 队列，效果等价于 `Promise.resolve().then(cb)`。
- **`requestAnimationFrame`**：既不是 task 也不是 microtask，是在渲染前单独的一步，时机早于下一个 task、晚于当前 task 的所有 microtask。
- **Node.js 的差异**：Node 事件循环分 timers/pending callbacks/poll/check 等多个阶段，且 `process.nextTick` 队列的优先级比 Promise 的 microtask 队列还高，每个阶段之间、每个 microtask 之间都会先清空 `nextTick` 队列。
