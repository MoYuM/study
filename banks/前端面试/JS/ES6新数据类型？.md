- Symbol（ES6 / ES2015）：唯一值，常用作对象的唯一属性键、定义常量，内置如 Symbol.iterator。
- BigInt（**ES2020**，并非 ES6）：表示超过 Number.MAX_SAFE_INTEGER 的大整数，字面量加 n（如 10n）。

补充：Set / Map / WeakMap / WeakSet 是 ES6 新增的内置结构（不是原始类型）。

## 追问

### 你列的这几个都是严格意义上的 ES6(ES2015) 新增的吗？

不全是。Symbol、Set/Map/WeakMap/WeakSet 都确凿是 **ES6(ES2015)** 新增；但 **BigInt 是 ES2020(ES11)** 才正式进入规范的，晚了整整 5 个年头，答"ES6 新数据类型"时把 BigInt 也算进去是常见的版本混淆。

### WeakMap/WeakSet 和 Map/Set 最核心的区别是什么？

**键的引用强度**：Map/Set 对键（Map 的 key、Set 的元素）持有**强引用**，只要 Map/Set 本身还活着，键指向的对象就不会被垃圾回收，哪怕业务代码里已经没有其他地方引用它了；WeakMap/WeakSet 对键持有**弱引用**，键对象一旦在其他地方失去所有引用，会被自动垃圾回收，对应的 WeakMap/WeakSet 条目也随之消失——因此 WeakMap/WeakSet 的键**只能是对象**（不能是原始值），且不可枚举（没有 `size`、`keys()`、`forEach()` 等遍历 API，因为条目何时被回收不可预测）。常用来给 DOM 节点或第三方对象挂关联数据而不必担心内存泄漏。

## 发展史（问题 → 方案的链条）

**❓ ES5 及以前，JS 只有 `Object` 一种通用键值结构，键只能是字符串（或被强制转换成字符串），没有原生集合类型，也没有能安全关联"外部对象"又不阻止其被回收的机制**
用 `Object` 模拟 Map 会遇到键只能是字符串（`obj[someObject]` 会把 `someObject` 强转成 `"[object Object]"` 这种没有区分度的字符串）、键会和 `Object.prototype` 上的内置属性（如 `toString`、`__proto__`）冲突、且对象里存的引用永远是强引用（想用 `object` 关联额外数据但不阻止它被回收，只能自己手写复杂的清理逻辑）这几个反复被吐槽的问题。

**✅ ES6（2015）一次性引入 `Map`/`Set`（键可以是任意值，且对键持强引用）**
解决了"键只能是字符串"和"和内置属性冲突"这两个问题，但键持强引用的特性没变——如果拿 Map 给 DOM 节点这类对象关联额外数据，只要 Map 不销毁，这些节点就永远不会被回收，反而制造了新的内存泄漏风险。

**❓ 给"外部对象"关联额外数据（如给 DOM 节点挂事件监听状态、给某个模块内部对象挂缓存）这个场景，如果用强引用的 Map，必须手动在对象销毁时同步删除 Map 里的条目，一旦漏删就是内存泄漏，而且开发者往往根本不知道这个对象什么时候该被清理**
需要一种"数据关联"结构：键存在时能正常查到值，但键本身在别处失去引用后能被垃圾回收，无需手动干预清理时机。

**✅ 同在 ES6（2015）引入 `WeakMap`/`WeakSet`，对键使用弱引用，垃圾回收器可以正常回收不再被外部引用的键**
代价是牺牲了可枚举性（引擎不能让开发者遍历一个"内容会随时被 GC 偷偷改变"的集合，否则遍历结果不可预测），换来了"关联外部对象数据、无需手动管理生命周期"的能力。

**现状：Map/Set（强引用、可枚举、有 size）用于"数据本身就该长期持有"的常规集合场景；WeakMap/WeakSet（弱引用、不可枚举、无 size）专用于"给外部对象挂临时关联数据、不应阻止其被回收"的场景——两者是根据"要不要阻止键被回收"这个正交需求分裂出的两套 API，不是功能强弱的差异**
