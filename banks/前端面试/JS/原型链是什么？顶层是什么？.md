对象通过 `__proto__` 指向构造函数的 `prototype`，逐级向上查找属性/方法，形成原型链。

## 三个关键名词（务必分清）

| 名词 | 挂在谁身上 | 指向谁 |
| --- | --- | --- |
| `prototype` | **函数**才有 | 用它 new 出来的实例的原型对象 |
| `__proto__` | **每个对象**都有 | 自己的上级原型 |
| `constructor` | 在 prototype 对象上 | 指回构造函数本身 |

```js
function Person() {}
const p = new Person();
p.__proto__ === Person.prototype          // ✅
Person.prototype.constructor === Person   // ✅
```

记忆钩子：`prototype` 是函数发给后代的「家谱」，`__proto__` 是每个对象攥着的「上一辈地址」，`constructor` 是家谱上写的「祖宗是谁」。

## 发展史（问题 → 方案的链条）

**❓ 语法要装 Java，语义想要 Self 的无类委托**
1995 年 Netscape 只给 Brendan Eich 10 天设计新脚本语言；当时 Netscape 与 Sun 合作推广 Java Applet，管理层要求语法必须像 Java 蹭热度。但 Eich 真正想搬进来的是另外两门语言的语义：Scheme（函数式，一等函数/闭包）和 Self（80 年代 Xerox PARC/Stanford 的 David Ungar、Randall Smith 设计，比 Smalltalk 更简单——完全不设「类」，一个对象自己没有的属性，直接转发给另一个对象「委托」查找）。语法要装 Java、语义想用 Self 式的无类委托，两者互相冲突。

**✅ 把「类」的角色安在函数身上，发明 `prototype` + `new`**
Eich 的折中是：给函数发明一个 `prototype` 属性，`new Fn()` 时创建新对象、并把这个新对象的内部委托指针连到 `Fn.prototype`。这样语法上像「实例化一个类」，底层其实还是 Self 式的委托查找。

**❓ 如果实例直接委托给 `Fn` 本身，会出问题**
上一步解决了"共享方法放哪"的问题，但如果图省事让实例直接委托给函数 `Fn` 自己（而不是另造一个对象），会有两个副作用：一是所有函数天生 `__proto__ === Function.prototype`（挂着 `call`/`apply`/`bind`），实例会因此意外"继承"到这些函数专属方法；二是没法区分"这个方法是给所有实例共用的"还是"只属于构造函数自己的"（也就是分不清实例方法和静态方法）。

**✅ 单独造一个 `Fn.prototype` 对象，专门当委托目标，和 `Fn` 本身分开**
不让实例委托给 `Fn`，而是单独造一个干净的普通对象 `Fn.prototype`，只用来放分给实例们共用的方法；`Fn` 自己保留函数身份（可调用、有 `Function.prototype` 那套），两者互不干扰。

**❓ 这根委托指针，开发者读不到也改不了**
上一步里"新对象连到 `Fn.prototype`"这个动作，靠的是 ECMAScript 规范里一个内部 slot `[[Prototype]]`。但 `[[Prototype]]` 不能直接读写——开发者既没法问"这个对象的原型到底是谁"，也没法绕开 `new Fn()` 直接指定一个已有对象作为原型（更贴近 Self 原本"克隆对象、改父指针"的写法）。

**✅ 早期引擎暴露非标准的 `__proto__`，直接读写这根指针**
网景/SpiderMonkey 等早期引擎给开发者暴露了一个非标准存取器属性 `__proto__`，可以直接 `obj.__proto__` 读、`obj.__proto__ = xxx` 写，绕开构造函数那一套。

**❓ `__proto__` 只是事实标准，没有进规范**
`__proto__` 长期只是各引擎自行实现的约定，不保证跨引擎行为一致，也没有被写进 ECMAScript 规范。

**✅ 标准化分两步落地**
`Object.getPrototypeOf()` 在 **ES5（2009）** 先进了规范，给出标准的读取方式；`__proto__` 本身连同 `Object.setPrototypeOf()` 直到 **ES6（2015）** 才正式写进规范——而且 `__proto__` 是作为 Annex B 遗留特性收编的，仅为兼容旧代码，标准场景更推荐用 `getPrototypeOf`/`setPrototypeOf`。

**现状：`prototype`（人造委托目标）与 `__proto__`（标准委托指针）并存，值相等、角色不同**
`Person.prototype` 是最初为模拟「类」而挂在函数身上的委托目标；`p.__proto__` 是后来逐步变成标准接口的、每个实例真正用来走到这个目标的委托指针。因为指针的终点恰好就是这个目标，所以 `p.__proto__ === Person.prototype`——两者名字像、值也相等，但一个是「目的地」，一个是「通往目的地的指针」，这正是这道题最容易踩的坑。

## 相关考点

- **`instanceof`**：本质是看「`B.prototype` 在不在 `a` 的原型链上」，挨个 `__proto__` 往上比对。
- **`Object.create(null)`**：造一个无原型对象，连 `toString`/`hasOwnProperty` 都没有，常用作纯净字典。
- **`hasOwnProperty`**：判断属性是对象自己的还是从原型链继承的（`in` 会连原型链一起算）。
