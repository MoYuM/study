流程：解析 HTML 生成 DOM 树、解析 CSS 生成 CSSOM → 合成渲染树（Render Tree）→ 布局 Layout（计算几何位置）→ 分层 → 绘制 Paint → 分块/光栅化（GPU 栅格化）→ 合成 Composite 显示。

- 回流（Reflow）：改变几何属性（尺寸/位置）触发 Layout，开销大。
- 重绘（Repaint）：改变样式但不影响布局（如颜色）。
- `transform` / `opacity` 走合成层，不触发回流重绘，性能最好。
- 优化：减少逐项操作 DOM（用 DocumentFragment / 批量）、避免强制同步布局（读写分离）、用 class 批量改样式。

## 解析阻塞：script 与 CSS

- **DOM 是边下载边解析、增量构建的**，不是等 HTML 全部下载完才开始建。
- 普通 `<script>`：解析到这里会**暂停 DOM 构建**，等脚本（外部脚本要先下载完）执行完才继续解析后面的 HTML。
- `defer`：**异步下载**，但等**HTML 解析完**（DOMContentLoaded 前）才按**书写顺序**依次执行——不阻塞解析。
- `async`：**异步下载**，**下载完立刻执行**，会**打断当前的 HTML 解析**；多个 async 脚本谁先下完谁先执行，顺序不确定。
- CSS（`<link>`）：不阻塞 HTML 解析本身，但**阻塞渲染**（渲染树需要 CSSOM）、也**阻塞其后面的 JS 执行**（JS 可能要读样式，浏览器需保证 CSSOM 已就绪）。
