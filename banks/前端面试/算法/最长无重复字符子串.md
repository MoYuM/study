滑动窗口 + Map 记录字符最近索引；左指针跳到重复字符下一位，更新最大长度。

```jsx
function lengthOfLongestSubstring(s) {
  const map = new Map(); let left = 0, max = 0;
  for (let r = 0; r < s.length; r++) {
    if (map.has(s[r]) && map.get(s[r]) >= left) left = map.get(s[r]) + 1;
    map.set(s[r], r);
    max = Math.max(max, r - left + 1);
  }
  return max;
}
```

时间 O(n)。

## 追问：左指针具体怎么移动？为什么不是逐格右移？

**不是**"逐步右移直到窗口里没有重复字符"（那样每次移动都可能要挪好几步，退化成 O(n²)）——而是**直接跳到重复字符上次出现位置的下一位**，一步到位。

Map 记录的不是"计数"，而是**每个字符最近一次出现的索引**。右指针遇到一个字符时：

- 查 Map 里有没有这个字符的记录
- **且这个记录的位置是否还在当前窗口内**（`map.get(s[r]) >= left`）——如果字符上次出现的位置已经被左指针甩到窗口外面了，就不算重复，不需要跳
- 如果两个条件都满足，说明窗口里确实还有这个字符，左指针直接跳到 `重复字符的索引 + 1`

**为什么必须判断"是否还在窗口内"**：Map 里存的是这个字符**历史上**最后一次出现的位置，可能早就被移出窗口了。如果不加这个判断，会误把已经不在窗口里的旧记录当成"当前重复"，导致左指针被错误地往回拉。

因为左右指针分别只会单调向右移动、且左指针每次都是"跳跃式"直达目标位置而不是一格格试探，整个算法左右指针总共只各走一遍 n 步，是 O(n) 而不是 O(n²)。

**记忆锚**：这是很多字符串/数组题（最小覆盖子串、无重复字符的最长子数组等）共享的"双指针滑动窗口"模板——右指针探路记录、左指针按需跳跃、`>= left` 判断是否还在窗口内，这三步是通用套路，建议对着代码手敲两遍建立肌肉记忆。
